# Project instructions

Before development, read `dev-brain/RULES.md`, `dev-brain/NOW.md` and `dev-brain/PROJECT_STATE.md`; consult the map and preferences as relevant.
Apply engineering principles proportionately to the actual language, framework and supported versions. Inspect existing code before proposing improvements; adopting the kit does not authorize application changes.
Preserve user work and existing instructions. Use the simplest complete, readable and verifiable solution, not merely the shortest diff.
At handoff, update NOW and state with actual results and next actions; update the map when stable facts change. Never import another repo's evidence or permissions.
Report real verification results and material limitations. Keep Git writes, destructive actions and publication within explicit authorization.
